# Граница математического модуля ПРИЗМА

## Цель

`prisma.analytics` является самостоятельным математическим пакетом. Он не
зависит от базы данных, ORM, FastAPI, Electron, React, файлов изображений и
бизнес-сервисов приложения.

Будущее приложение должно обращаться только к публичному API:

```python
from prisma.analytics import analyze_session, compare_analysis_modes
```

Прямые импорты внутренних файлов математического модуля из приложения не
предполагаются.

## Структура моделей аналитики

```text
prisma/analytics/models/
    __init__.py       единая публичная точка импорта моделей
    common.py         только общие типы идентификаторов и матриц
    enums.py          режимы и варианты математических алгоритмов
    inputs.py         минимальные входные контракты аналитики
    observations.py   промежуточные решения по повторным наблюдениям
    results.py        результаты, trace и JSON-сериализация
```

Файл `__init__.py` является фасадом. Внутреннюю раскладку можно менять без
изменения импортов вызывающего кода.

## Входные контракты не являются бизнес-моделями

`CollectionSchema`, `CollectionItem`, `PairResponse` и `SessionMetadata` внутри
`prisma.analytics.models.inputs` содержат только сведения, необходимые для
воспроизводимого расчёта. Это не ORM-сущности и не модели экранов приложения.

В будущих бизнес-моделях могут дополнительно находиться:

- состояние коллекции и правила её активации;
- пути и метаданные файлов;
- пользователи и роли;
- даты создания и изменения;
- связи базы данных;
- настройки интерфейса и отчётов.

Эти сведения не должны попадать в математическое ядро, если они не участвуют в
формуле или проверке входных данных.

## Направление зависимости

```text
бизнес-модели приложения
        ↓
тонкий адаптер входных данных
        ↓
публичные контракты prisma.analytics
        ↓
математический расчёт
        ↓
сериализуемый результат аналитики
```

Математический модуль никогда не импортирует модели приложения. Поэтому его
можно заменить новой реализацией, сохранив внешний контракт либо изменив только
тонкий адаптер, а не весь основной проект.

## Правило для дальнейшей разработки

- Математические входы, промежуточные структуры и результаты остаются внутри
  `prisma.analytics`.
- Пользователи, роли, коллекции как редактируемые сущности, сессии хранения и
  другие модели приложения создаются вне `prisma.analytics` на соответствующем
  этапе.
- Формулы не переносятся в бизнес-модели, API или TypeScript-клиенты.
- Внешний код использует фасад `prisma.analytics`, а не внутренние файлы.
