# ПРИЗМА: решения по математическому ядру

Версия baseline: `prisma-analytics/0.6.0-level-majority`.

Контрольные источники: `Попарное сравнение.xlsx` и
`Входящие данные и их отбор.xlsx`, листы `Лист1`.

## CONFIRMED

1. Глубина — нечётное число повторных наблюдений каждой пары типов. На каждом
   уровне сравниваются все типы попарно, но только изображения одного столбца.
   Межуровневые сравнения запрещены. Рейтинг отдельного уровня не строится.
2. Для каждой пары определяется тип, выбранный в большинстве наблюдений.
3. Из большинства всегда остаются ровно два наблюдения с минимальным временем.
   Более медленные ответы большинства и все ответы меньшинства сохраняются в
   trace, но не участвуют во временном расчёте.
4. Два выбранных времени не складываются в одно `T_ij`. Они занимают две
   противоположные ячейки матрицы времени. Поэтому для `n` типов используется
   `n*(n-1)` временных значений.
5. Общее время `T` — сумма всех направленных внедиагональных ячеек матрицы
   времени. В примере XLSX `T=23124`.
6. Бинарная матрица `P` строится по победителям большинства. Для неё обязательно
   `p_ij+p_ji=1`; нарушение останавливает расчёт как ошибка данных.
7. В `source_v1` каждая направленная ячейка `P*` рассчитывается независимо:

   ```text
   v_ij  = 1 - T_ij/T
   p*_ij = p_ij*v_ij + (1-p_ij)*(1-v_ij)
   ```

   При разных временах двух выбранных наблюдений `P*` не обязана быть
   симметрично-дополнительной.
8. Новое значение веса — сумма произведений элементов одной строки матрицы на
   соответствующие элементы предыдущего вектора. Все строки используют один и
   тот же неизменный предыдущий вектор.
9. После полного построчного шага новый вектор нормализуется. Начальный вектор:
   `W(0)=[1,...,1]`.
10. Сходимость достигнута, когда максимальное изменение координаты меньше
    `epsilon`; baseline `epsilon=0.001`.
11. Если `zeta<0.5`, возвращаются `preferences_not_identified`, сообщение
    «Предпочтения не выявлены» и отсутствие рейтинга.
12. Для `width=2` `Cmax=0`, поэтому `zeta=null`. Проценты равны фактическим
    частотам выбора.
13. Timeout не заменяется вымышленным выбором. Вся повторная серия пары
    считается неполной, а идентификаторы картинок остаются в trace.
14. Глубина `1` разрешена для коллекции и `choice_only`. Для временного режима
    невозможно выбрать два наблюдения большинства, поэтому он честно возвращает
    `insufficient_time_data`, не дублируя единственный ответ искусственно.

## CLARIFICATION

1. Матрица в `Входящие данные и их отбор.xlsx` визуально использует ячейку
   «строка проигравшего, столбец победителя». В Python сохраняется ранее
   утверждённое определение `p_ij=1`, если тип строки `i` выбран вместо типа
   столбца `j`. Поэтому программная матрица является транспонированным
   представлением показанной таблицы, но кодирует те же шесть победителей.
2. После выбора двух самых быстрых наблюдений они возвращаются в исходный
   порядок предъявления. Первое заполняет верхнюю каноническую ячейку пары,
   второе — противоположную. Это детерминированное правило необходимо, потому
   что XLSX показывает две ячейки, но не содержит исходных номеров предъявлений.
3. При одинаковом времени отбор выполняется по меньшему `comparison_index`.
4. Диагональ хранится как `NaN`, в JSON сериализуется как `null` и в суммах не
   участвует.
5. Добавлены `max_iterations`, `zero_normalization_sum` и
   `max_iterations_reached`. При несходимости сохраняется последний корректный
   вектор и trace, но официальный рейтинг не публикуется.
6. В XLSX в формулах первой строки итераций (`B26`, затем `B28`, `B30` и т.д.)
   между первым и вторым произведением пропущен знак `+`. Остальные три строки
   используют сумму произведений, и авторская сторона ранее явно описала именно
   сложение всех произведений строки. В Python знак восстановлен. Поэтому
   кэшированный итог XLSX не используется как правильный ожидаемый рейтинг.

## PROPOSAL

1. `choice_only` временно использует `self_retention_prototype_v1`:

   ```text
   новое значение = предыдущее значение типа + сумма произведений строки P
   ```

   Это предотвращает нулевой вектор на строго согласованной бинарной матрице.
   Формула остаётся рабочим допущением до проверки специалистом.
2. `symmetric_candidate_v2` оставлен только для сравнения. Верхняя ячейка
   считается по XLSX, а противоположная принимается равной `1-p*_ij`. Это не
   baseline и включается только явно.
3. При `width=2` временная матрица сохраняется как диагностика, но временная
   поправка пока не меняет частотные проценты.
