# ПРИЗМА: решения по математическому ядру

Версия рабочего прототипа: `prisma-analytics/0.4.0-prototype`.

## CONFIRMED

1. Уровни глубины являются повторными наблюдениями одной и той же
   неупорядоченной пары типов. Отдельный рейтинг каждого уровня не строится.
2. Для каждой пары типов ответы всех уровней делятся по выбранному типу.
   Победителем становится тип из большей группы.
3. Из большей группы всегда выбираются **ровно два** наблюдения с минимальным
   `reaction_time_ms`, даже если большинство содержит 3, 4 или 5 наблюдений.
   При равном времени tie-breaker — меньший `comparison_index`.
4. Наблюдения меньшей группы и более медленные наблюдения большинства не входят
   во временной расчёт, но сохраняются в trace.
5. Время пары:

   ```text
   T_ij = time(fastest majority observation 1)
        + time(fastest majority observation 2)
   ```

   Общее время:

   ```text
   T = sum(T_ij for every unordered type pair)
   ```

6. `P` строится один раз для коллекции по победителям большинства.
7. `p_ij+p_ji=1` — обязательный инвариант. Запись `p_ij+p_ji≠1` означает
   условие завершения расчёта как невалидного, а не второе свойство матрицы.
8. Упоминание четырёх образов относится к реальному тесту, а матрица `5×5` в
   документе является отдельным примером произвольной ширины.
9. После временного преобразования `P*` не обязана удовлетворять
   `p*_ij+p*_ji=1`.
10. Быстрый выбор означает более выраженное предпочтение. В `source_v1`
    направленное преимущество выбранного типа над невыбранным равно
    `v_ij=1-T_ij/T` независимо от расположения победителя в верхнем или нижнем
    треугольнике.
11. Если `zeta<0.5`, возвращаются:

    ```text
    status = "preferences_not_identified"
    message = "Предпочтения не выявлены"
    overall = null
    ```

12. Baseline `epsilon=0.001`; параметр задаётся явно и не изменяется
    автоматически.
13. При двух типах проценты считаются как фактическая частота выбора каждого
    типа. Например, три выбора из пяти дают `60%`, два из пяти — `40%`.
14. Timeout исключает соответствующую пару из рейтинга. В trace сохраняются
    идентификаторы левой и правой картинки, их типы, номер предъявления, время,
    статус и отсутствие выбора.

## SOURCE BASELINE

1. Для `i<j`:

   ```text
   p*_ij = p_ij*v_ij + (1-p_ij)*(1-v_ij)
   ```

2. Для `i>j` основной `source_v1` буквально использует:

   ```text
   p*_ij = 1-p_ji
   ```

3. Диагональ `P` и `P*` равна `NaN` и в расчёте не участвует.
4. Новая координата веса считается по одной строке матрицы:

   ```text
   w_i(k+1) = sum(p*_ij * w_j(k) for j != i)
   ```

   Во время расчёта всех строк предыдущий вектор `W(k)` не изменяется. После
   расчёта полного нового вектора выполняется нормализация.
5. Добавление собственного предыдущего значения источником и фотографией
   ручного расчёта не подтверждается. Поэтому во временном режиме baseline оно
   не применяется.

## IMPLEMENTATION CLARIFICATIONS

1. Сначала ответы группируются по неупорядоченной паре типов через все
   `level_index`, затем выполняется majority/fastest-two preprocessing.
2. Для полного реального расчёта каждая пара должна иметь отвеченное наблюдение
   на каждом уровне. Timeout или отсутствующий ответ делает пару
   `incomplete_pair`; пропущенный выбор не угадывается.
3. Нечётная глубина полного набора гарантирует отсутствие равенства голосов.
   Проверка `unresolved_tie` сохранена как защитная диагностика.
4. Выбранные наблюдения маркируются `selected_fastest_majority`. Остальные роли:
   `discarded_slower_majority`, `discarded_minority`, `timeout`.
5. `pair_time_matrix_ms` содержит `T_ij`, а `validation_total_time_ms` — `T`.
6. Итерация реализована явным двойным циклом. Для каждой строки сохраняются
   ненормированный результат (`raw_vectors`) и нормированный полный вектор
   (`normalized_vectors`). Оператор матричного умножения (`@`, `matmul`, `dot`)
   не вызывается: элементы конкретной строки по одному умножаются на элементы
   предыдущего `W`, после чего произведения складываются.
7. Добавлены защитные `max_iterations`, `zero_normalization_sum` и
   `NON_CONVERGED`. Последний корректный вектор и весь trace сохраняются;
   официальный `overall` для несошедшегося режима равен `null`.
8. Диагональ хранится как `NaN` внутри NumPy и сериализуется как JSON `null`.
9. Для одинакового времени двух кандидатов используется `comparison_index`,
   обеспечивая детерминированность.
10. Choice+time по умолчанию использует буквальную построчную итерацию над
    временной матрицей. Как уточнила авторская сторона, дробные элементы
    временной матрицы не дают описанной нулевой цепочки.
11. Choice-only по умолчанию использует отдельную рабочую стратегию
    `self_retention_prototype_v1`, описанную ниже. В результате и trace всегда
    записывается фактически применённая стратегия.

## WORKING ASSUMPTIONS

1. Для сходимости режима choice-only принято временное правило:

   ```text
   новое значение типа
   = его предыдущее значение
   + сумма произведений по строке бинарной матрицы
   ```

   Это минимальное техническое дополнение не меняет элементы исходной матрицы,
   предотвращает нулевой вектор и даёт рабочий рейтинг для просмотра прототипа.
   Правило имеет имя `self_retention_prototype_v1` и помечено как `PROPOSAL`.
2. При `width=2` коэффициент согласованности по триадам неприменим:
   `zeta=null`, `consistency="not_applicable"`.
3. При двух типах оба режима показывают наблюдаемую частоту выборов. Временная
   матрица сохраняется для диагностики, но не изменяет эти проценты.
4. При timeout вся повторная серия соответствующей пары считается неполной,
   даже если среди оставшихся ответов уже видно большинство. Это исключает
   угадывание отсутствующего выбора.

## EXPERIMENTAL / NOT APPROVED

1. `symmetric_candidate_v2` сохранён только для диагностики и вызывается явно.
   Baseline — `source_v1`.
2. Прежнее `mean_v1` удалено из основного API. Среднее рейтингов уровней не
   соответствует подтверждённой роли глубины.
3. Буквальная стратегия `literal_source_v1` доступна явным параметром и для
   choice-only. Она сохранена для воспроизведения исходной проблемы нулевого
   вектора, но не является настройкой рабочего прототипа по умолчанию.

## OPEN

1. После просмотра прототипа требуется подтвердить или заменить
   `self_retention_prototype_v1` для choice-only.
2. Формулировка обратной части временной матрицы пока остаётся буквальной по
   документу; `symmetric_candidate_v2` не утверждён.
3. Для двух типов временная поправка пока только диагностическая; при
   необходимости нужна отдельная научная формула.

## Не входит в текущий этап
