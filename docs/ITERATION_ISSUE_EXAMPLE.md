# Пошаговая диагностика и рабочее допущение сходимости

Рассматривается матрица полностью согласованных выборов без циклических триад:

```text
P = [[NaN, 1, 1, 1],
     [0, NaN, 1, 1],
     [0, 0, NaN, 1],
     [0, 0, 0, NaN]]
```

Подтверждённая ручным примером операция для каждой строки:

```text
raw_i(k+1) = sum(P_ij * W_j(k) for j != i)
```

Один и тот же `W(k)` используется для всех строк; диагональ пропускается.

```text
W(0) = [1, 1, 1, 1]

raw(1) = [3, 2, 1, 0]
W(1)   = [1/2, 1/3, 1/6, 0]

raw(2) = [1/2, 1/6, 0, 0]
W(2)   = [3/4, 1/4, 0, 0]

raw(3) = [1/4, 0, 0, 0]
W(3)   = [1, 0, 0, 0]

raw(4) = [0, 0, 0, 0]
sum(raw(4)) = 0
```

При `epsilon=0.001` изменения первых трёх нормированных векторов равны `0.25`,
поэтому критерий до нулевой суммы не выполнен.

Результат буквального диагностического режима `literal_source_v1`:

```text
status = "NON_CONVERGED"
iteration.status = "zero_normalization_sum"
iterations = 4
last_vector = [1, 0, 0, 0]
```

Во временном режиме эта проблема не воспроизводится, поскольку после учёта
времени в строках остаются дробные ненулевые элементы. Поэтому choice+time
продолжает использовать буквальную операцию без собственного слагаемого.

Для первоначально работающего choice-only прототипа принято явное допущение:

```text
raw_i(k+1) = W_i(k) + sum(P_ij * W_j(k) for j != i)
```

Оно не записывается на диагональ исходной матрицы и не изменяет сохранённую
матрицу ответов. Предыдущее значение добавляется только на этапе итерации.

Для показанного примера стратегия `self_retention_prototype_v1` сходится за 52
итерации при `epsilon=0.001`:

```text
W = [0.946429, 0.051623, 0.001912, 0.000036]
```

Порядок соответствует исходной полностью согласованной последовательности.
Допущение является `PROPOSAL` и должно оцениваться по результатам прототипа.
