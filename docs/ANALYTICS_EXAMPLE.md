# Проверяемый пример из `Попарное сравнение.xlsx`

Типы: Инженер, Архитектор, Врач, Пилот. Глубина в прототипе должна быть
нечётной; для каждой пары сначала определяется большинство, затем из него
берутся два самых быстрых наблюдения.

## 1. Бинарный выбор

```text
P =
              Инж.  Арх.  Врач  Пилот
Инженер        NaN     1     1      1
Архитектор       0   NaN     0      0
Врач             0     1   NaN      1
Пилот            0     1     0    NaN
```

Получен строгий порядок: Инженер > Врач > Пилот > Архитектор.

Для четырёх типов `C=0`, `Cmax=2`, `zeta=1`.

## 2. Два времени каждой пары

XLSX задаёт не одно суммарное время пары, а две противоположные ячейки:

```text
T_ij, мс =
              Инж.  Арх.  Врач  Пилот
Инженер        NaN  2694   390   1227
Архитектор    2217   NaN  2400   2514
Врач          1238  2549   NaN   1730
Пилот         1456  2492  2217    NaN
```

```text
T = сумма всех 12 значений = 23124 мс
```

## 3. Матрица с учётом времени

Каждая внедиагональная ячейка считается по своему времени:

```text
v_ij  = 1 - T_ij/T
p*_ij = p_ij*v_ij + (1-p_ij)*(1-v_ij)
```

```text
P* source_v1 =
[[NaN,      0.883498, 0.983134, 0.946938],
 [0.095874, NaN,      0.103788, 0.108718],
 [0.053537, 0.889768, NaN,      0.925186],
 [0.062965, 0.892233, 0.095874, NaN     ]]
```

## 4. Итерация весов

Старт: `W(0)=[1,1,1,1]`.

Первая строка первого шага должна быть суммой трёх произведений:

```text
raw_Инженер = 0.883498*1 + 0.983134*1 + 0.946938*1
             = 2.813570
```

Полный ненормированный вектор:

```text
raw(1) = [2.813570, 0.308381, 1.868492, 1.051072]
```

После каждого шага все значения делятся на их сумму. На девятой итерации
максимальное изменение примерно `0.000866<0.001`.

```text
W = [0.498910, 0.094859, 0.258721, 0.147509]
```

## 6. Почему числа отличаются от кэша XLSX

В ячейке `B26` и её копиях формула записана без одного знака `+`:

```text
C25*C18*D25*D18 + E25*E18
```

Это перемножает первые два произведения между собой. В остальных строках
записана обычная сумма трёх произведений. Python реализует сформулированное
правило: «умножить попарно элементы строки и предыдущего вектора, затем сложить
полученные произведения». Ошибка XLSX не переносится в baseline молча; она
закреплена отдельным тестом и решением в `ANALYTICS_DECISIONS.md`.

## Отбор входных наблюдений по уровням

Файл `Входящие данные и их отбор.xlsx` задаёт четыре типа и три изображения
каждого типа. Для каждого столбца независимо строятся все шесть пар:

```text
уровень 1: 11–21, 11–31, 11–41, 21–31, 21–41, 31–41
уровень 2: 12–22, 12–32, 12–42, 22–32, 22–42, 32–42
уровень 3: 13–23, 13–33, 13–43, 23–33, 23–43, 33–43
```

Пары `11–21` и `13–43` допустимы, потому что оба элемента пары находятся в
одном столбце. Пара `11–22` запрещена. После прохождения три ответа каждой пары
типов объединяются большинством. Например, Архитектор выбран против Инженера
на уровнях 1 и 2, а Инженер — на уровне 3, поэтому итог пары: Архитектор `2:1`.

По всем шести парам получается порядок:

```text
Архитектор > Пилот > Врач > Инженер
```

В XLSX победитель отмечен в столбце, а в Python `p_ij=1` означает победу типа
строки. Поэтому программная `P` визуально транспонирована относительно таблицы
XLSX, сохраняя те же результаты пар.
